## Planned changes, skips, refills, backup protection (owner request)
- Planned changes (`medication.plannedChanges`): a dated future schedule and usual dose, e.g. one per taper step. Applied
  on its user day at start-up (before the first screen, so a morning tag tap already uses it) and every 5 minutes; each is
  recorded as a dated `changed` event. "Plan a change" reuses the schedule editor (`ScheduleFields`). Today shows
  "Changes Fri 23 Oct: …" in the week before; Meds shows "Change planned from …".
- Skipped doses (`dose.skipped`, `skipReason`): hold their place in the day's plan (next amount/set time moves on; the
  interval rhythm continues from the skip) but never count as taken, never change stock, and aren't the "last dose".
  Shown in the timeline, report and CSV; excluded from charts.
- Refill forecast (`logic/plans.ts`): walks the plan day by day (including planned changes) until stock can't cover a
  day; as-needed and open-ended plans use the last 30 days' use. Repeats left and script expiry on the medication.
  Today card when at/below the low-stock number, running out within "warn me N days ahead" (default 7) or script
  expiring within 30 days; Add stock (optionally uses a repeat, with undo).
- Backup files are always encrypted (AES-256-GCM) with a key built into the app (owner decision: no password). Opening a
  file, or a cloud/email preview, shows scrambled text; any copy of the app restores it with no password. The key is in
  public code, so this deters casual reading, not a determined attacker. NEVER change `BACKUP_KEY` in `logic/crypto.ts`,
  or older backups can't be restored. Plain (unencrypted) backups from before still restore.
- Automatic backups: File System Access folder (Chrome desktop / recent Android Chrome), daily when the app is open,
  keeps the last N; Today card if the browser needs permission again. Elsewhere (iPhone): "Remind me every N days".
  The folder permission is kept in the device-only `device` table (DB v3), never backed up.

## Decisions
- Working title `MedTap` (src/config.ts + vite.config.ts manifest). Change when owner confirms APP_NAME.
- **Permanent address (owner decision): https://lumenbuild.github.io/MedTap/** — no custom domain, ever. Tags are
  `https://lumenbuild.github.io/MedTap/?t=<ID>`. The workflow pins `VITE_TAG_BASE` to it and fails the build if the repo
  is renamed (Pages doesn't redirect after a rename, so every tag would break). Local/dev builds without
  `VITE_TAG_BASE` use the current address and show a "test address" warning when linking a tag.
- Dose `amount` is in the medication's unit (e.g. mg). Stock counts tablets/items and goes down by amount ÷ strength
  (shown to the user in the editor).
- Doses later than `now` don't count towards "today" (matters for backdated context notes).
- Set-times: a dose within ±60 min covers a time. Once a time's window closes unlogged, the countdown moves to the next one;
  if none remain and the day isn't complete, status is "past your latest dose time".
- Interval: countdown starts from the first dose of the user's day; before it, "No doses yet today".
- Theme preference is in localStorage (display pref only); records are IndexedDB only.
- Live data uses Dexie's built-in `liveQuery` via a tiny `useLive` hook (no extra dependency).
- Check-in scales are five large buttons (1–5) rather than sliders: easier with a thumb and can be left unanswered.
- An every-few-hours plan with a daily number has no "next dose" once complete (status Done for today).
- Not supported yet: calendar-month schedules (e.g. the 1st of each month); use every 28/30 days instead.
